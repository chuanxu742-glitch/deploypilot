# 持续终端与历史恢复

2026-10-29，ui11。本机版本已启动，旧进程保留；未提交或推送。主代理实现后台及原生验证，Luna 实现前端与浏览器回归。

## 原因与改动

旧版 Agent 每条命令创建独立进程，人工终端另有 PTY，因此目录和环境不共享。任务绑定 WebSocket，断线会取消；页面内存中的事件刷新后消失。现在 Shell 和任务由后台持有，页面只是订阅者。Agent 与人工使用同一 Shell，任务运行、停止清理期间不接受人工输入。切换目录也作用于后续相对路径文件工具。

首次连接与重连先恢复任务快照，再接收带任务标识和事件序号的更新；前端不重复发送 start。历史任务只通过 GET 加载。终端先重置显示，再回放最近输出，重连不新建 Shell。

历史以逐任务文件和索引保存在用户本机，旧记录不因新任务被删除。原生文件锁防止同一工作目录多个新版进程覆盖历史；损坏文件或存储故障明确报错，原文件不被清空。首次升级从旧审计日志恢复已经记录的事实，原日志保留。实际新版已导入 22 条旧任务。

真实浏览器联调发现 XTerm 的焦点通知会误清除 Shell 就绪状态；已区分焦点、终端能力回复与人工输入，并补回归。

## 边界

- 页面刷新/断线不取消任务；认证过期、撤销授权、明确停止或程序退出仍会取消。
- 程序重启恢复记录、最近终端输出和最后目录；未完成任务标中断，不自动重跑。原进程、Shell 临时变量及环境修改不能跨程序重启恢复。
- 每个任务保留最近 512 条事件、约 512 KiB 过程内容；终端回放有 2 MiB 上限。历史任务索引及独立记录不因新任务删除。旧版未保存的聊天过程不能重建。
- 本轮原生交互在 Windows PowerShell 验证；Linux 的共享 Bash 路径未作实机验证。未运行 race 检测，本机 Go 的 CGO_ENABLED 为 0，未配置 C 编译器。
- 真实浏览器联调用的模拟模型没有调用 finish，因此页面正确显示任务未确认完成；本次验证的是会话执行与恢复，不把它当部署成功证据。
