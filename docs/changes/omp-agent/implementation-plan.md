# 实施计划

1. executor.go：保留短输出原文；超长输出在原 16 KiB 内容容量内保留头尾、明确截断，处理跨写入 UTF-8 边界，不增加磁盘落盘。测试超长单块、多块、中文边界和末尾错误。
2. context.go：先截短旧轮工具输出，再汇总旧轮，最近一轮尽量保持完整；只有其自身加受保护前缀超出预算时才缩短/汇总它。继续保留完整调用结果配对和原始目标。测试旧轮可回收时最新结果不丢，以及单轮过大仍有硬上限。
3. agent.go：普通文字/空回复最多提示一次显式 finish；仍不调用 finish 则给失败结果并返回错误，取消不能变成成功。每个工具调用的参数错误、拒绝、命令非零退出和文件错误都发布结束事件，带失败状态和错误信息；不以字符串前缀猜测正常文件内容是否错误。已有 finish.success 保留语义，不据任意探测命令退出 0 推断部署成功。
4. 以本地模型模拟和 fake Executor 为主，先记录目标测试红阶段；修复后跑 agent/server 回归、全套 Go 测试、go vet、前端既有状态测试及 Windows/Linux amd64/arm64 构建。检查成功/失败事件和原界面状态逻辑兼容。收尾用 eri-comment-maintenance、eri-verification 核对注释与证据。

验收：O1 长日志尾部不再因前缀上限丢失；O2 最新一轮在可容纳时不被旧历史挤掉；O3 工具失败有且只有一个对应结束事件，正常 error: 文本文件不报错；O4 非 finish 回复不会假成功，提示有上限，合法 finish 仍可完成；O5 回归与构建通过，明确未验证项。本轮不承诺完整日志可恢复、精确 token 计数或后台任务续接。
