# Agent 循环优化

分支 `feat/agent-loop-improvements`。目标是让长部署任务能跑完、失败后能接着做，并修掉部署场景下的几个实际问题。

## 改动

### 能跑完、能接着做

1. **断线重试本轮**：模型流在 `[DONE]`/`finish_reason` 前断开（或读取出错）时，`llm` 标记为 `ErrStreamInterrupted`；agent 重新请求本轮，最多 2 次，并在记录里提示可能出现重复文字。这类响应不会执行任何工具，所以重试安全。格式错误、`length`、非法工具调用等确定性错误不重试。`StreamChat` 自身仍然不重放。
2. **上下文超长自动恢复**：供应商以 400/413 报上下文超长时，把字节预算收紧三分之一（下限 16 KiB）并重新压缩，最多 2 次。
3. **续跑**：每一轮都完整记录（停止或 `finish` 时，未执行的工具调用补上“未执行”结果，保证配对合法）。服务端在内存里保留最近一次运行的上下文，快照里以 `continuable` 标出；前端在该任务未确认成功时默认勾选「在此任务上继续」，发送 `continueFrom`。追加指令按时间顺序进入上下文，被压缩掉时会在请求开头重述，不会丢失。
4. **步数**：默认从 30 提高到 40，`DP_MAX_STEPS` 可调（5–200）。步数用完时提示可以继续。
5. **向操作员要信息**：system prompt 说明需要密码、令牌等信息时用 `finish(success=false)` 写清需要什么，操作员可在该任务上继续补充。

### 部署场景

6. **环境探测**：共享 Shell 改造后只剩 `pwd`，现在恢复为完整探测：系统、用户与免密 sudo、CPU/内存、磁盘、GPU、CUDA、Python/pip、Docker 守护进程可达性、systemd、网络。并行执行、作为独立只读进程运行（不进入操作员终端），Windows 有 PowerShell 版本。修了原来永远不会打印回退信息的 CUDA 探测。
7. **PowerShell 输出强制 UTF-8**：中文 Windows 上命令输出原本是 GBK，非 ASCII 文字会丢失。
8. **system prompt 与 `run_command` 说明**：持久终端（不要 `exit`、不要单独 `set -e`）、无法交互（`sudo -n`，不用 vim/less/top）、长期服务放后台并写日志再轮询、慢命令设 `timeout_seconds`、非零退出码不一定是故障。
9. **`edit_file`**：解析符号链接后修改真实文件（不再把链接替换成普通文件），使用唯一临时文件，保留权限和属主（root 编辑时）。
10. **`read_file`**：含 NUL 的文件按二进制拒绝并给出替代命令；分页在完整字符处结束。
11. **黑名单**：新增 Windows 规则（磁盘/引导破坏、递归删除盘符根目录或 Windows 目录、关机重启）、`/dev/xvd*`、去引号后再检查（`rm -rf "/"`）。

### 模型后端兼容

12. **`finish_reason: "stop"` + 工具调用**：部分 vLLM/Ollama 版本这样返回，现在视为 `tool_calls`（工具调用本身仍完整校验）。
13. **限流重试**：最多 6 次（0.5s 起指数退避，约 15 秒），429/5xx 按 `Retry-After` 等待（上限 60 秒）。

## 刻意未做

- **非零退出码显示为错误**：既有测试 `TestToolFailuresHaveOneCompletionAndError` 明确要求非零退出码以 `error:` 返回给模型并产生错误事件。改成中性显示会推翻这个设计，所以只在 system prompt 里说明非零不一定是故障。
- **合并两条 system 消息**：既有测试依赖“第 0 条为 system、第 2 条为原始任务”的结构；收益不确定，保持原状。
- **token 用量统计**：需要在请求里加 `stream_options`，部分 OpenAI 兼容后端会拒绝未知参数，可能让白鹿接口直接报错，未做。
- **黑名单覆盖 `write_file` 写出的脚本**：黑名单定位是兜底，做不到沙箱级别，未扩展。
- **续跑上下文持久化**：上下文只在内存里，程序重启后不能继续。持久化需要处理大小和敏感内容，暂不做。
