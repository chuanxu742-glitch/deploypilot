# 实施计划

依据：没有 SDD；依照用户明确要求的跨版本排查和底层错误日志补齐。

工作模式：`eri-implementation`，按“可改旧代码，限最小改动”处理已有调用路径。先用真实子进程替身补失败日志用例并见红，再实现；每片重读本计划核对范围。

## 文件与行为

- `client/internal/tunnel/diagnostics.go`（新增）：每次进程独立日志，限制文件与内存用量，过滤配置/凭证和终端控制字符，提供简短底层错误摘要及日志路径。日志写入失败明确报告，不阻断隧道本身。
- `client/internal/tunnel/tunnel.go`：持续读取子进程全部输出，保留 URL 解析；启动失败、进程退出和超时附诊断信息，超时区分尚未取得 URL 与已取得 URL 但没有首次连接。默认时限、进程所有权和就绪判据不变。
- `client/cmd/deploypilot/main.go`：启动重试前结束会截断文字的进度行，用已有完整状态输出打印失败详情，再恢复进度；退出清理始终指向当前进度对象。
- `client/internal/tunnel/reliability_test.go`、`diagnostics_test.go`：覆盖 URL 后出错、两种超时阶段、日志失败、敏感值过滤、超长输出和退出清理。
- `README.md`：说明日志文件位置、限制及排查方式。
- `.probe-tmp/tunnel-diagnostics/`：存放对照脚本、官方校验过的版本文件、原始日志和本机记录，不纳入提交。

## 版本对照

同一 Windows 主机、同一现有 Clash 模式/节点，对照 `2026.9.3`、当前 `2026.10.5`、最新正式版 `2026.10.7`。每版分别使用默认协议和强制 HTTP/2；各次使用独立空配置和测试页面，最长 65 秒。记录网址是否取得、首次连接是否就绪、底层错误、代理状态是否变化。临时进程结束后回收；不暴露 DeployPilot 控制台或真实文件。

## 检查安排

1. 改前 `go test ./internal/tunnel -count=1 -timeout=60s`。
2. 每片定向测试；全部实现后运行 tunnel、入口和 banner 包测试及 `go vet ./...`。
3. 完成后运行一次 `go test ./... -count=1 -timeout=120s`（已有历史记录通常数十秒；真实模型和公网测试默认不启用），构建 Windows 本机版本。
4. 实际运行新构建入口，确认失败提示包含底层原因与可读日志路径；保全旧安装文件后在用户实际安装位置核验。若环境权限阻止必要动作，如实保留未完成项。

不动：默认依赖版本（除非版本对照取得充分证据）、代理节点/规则、120 秒默认时限、5 次失败重试策略、配对与认证、终端/Agent/前端行为、公开发布和推送。
