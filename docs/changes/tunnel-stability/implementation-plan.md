# 实施计划

授权：用户“还有内网穿透的稳定性也要做好，现在的稳定性怎么样”。以下是范围内实现选择，未声称用户逐份批准文档。

1. tunnel 启动：同时排空两路输出、限制日志解析内存；网址和本次进程首次连接确认同时具备才返回。使用唯一临时目录 pidfile 核对本进程 PID；120 秒可取消启动期限，兼顾协议回退；失败和退出收回进程及临时文件。
2. tunnel 维护循环：启动失败或进程退出后按 1/2/4/8 秒等待，连续 5 次失败终止并报错；运行超过 1 分钟重置失败计数。先撤销旧会话和配对 token，重新就绪后生成新 token 与二维码；不重放任务。主入口所有错误路径关闭本地服务。短时断网依赖 cloudflared 的原生重连，不主动更换域名。
3. 下载：等待响应头也纳入现有 10 秒低速窗口；每次下载独立临时文件并清理，已取消不再尝试其他镜像，验证后才替换缓存，正确处理关闭失败。
4. WebSocket：25 秒 ping、75 秒无 pong 判为失联并关闭；心跳不续认证寿命。保持既有任务取消与跨连接互斥语义。
5. 先为旧接口添加目标失败测试，再改实现；新增维护循环、token 更新做行为测试。使用本地 HTTP/WS 服务和真实测试子进程模拟慢源、崩溃和失联，不对用户真实网络注入故障。最后 Go 全套测试、vet、三平台构建；实际 cloudflared 可用性若验证，仅暴露无权限的测试服务，不暴露控制台或凭证。没有长时间公网测试不得宣称生产稳定或承诺在线率。

验收：T1 stdout URL/大日志不堵塞；T2 未连接不就绪、取消无残留；T3 失败重试、退避与取消、重配对撤销有效；T4 响应头卡住可切源、并发下载互不破坏、取消清理；T5 无 pong 关闭、正常 pong 保活且不延长认证；T6 调用入口构建和全套回归通过，明确公网和长期稳定性局限。
